# Upgrading to 0.2.0

0.2.0 moves each command's main subject from a flag to a positional argument, and lets ushabti infer the project from a ticket id. Nothing breaks: every old flag keeps working and prints a `warning:` line to stderr. Plan to migrate, since the deprecated flags will be removed in a future release.

## What to change

| Before | After |
|---|---|
| `jira fetch --project ABC` | `jira fetch ABC` |
| `jira fetch --project ABC --id ABC-123` | `jira fetch ABC-123` |
| `jira comments --id ABC-123` | `jira fetch ABC-123` (writes `ABC-123.comments.md` next to the ticket; `jira comments` itself is deprecated) |
| `jira create --project ABC --file t.md` | `jira create t.md ABC` |
| `jira update --file ABC-123.md` | `jira update ABC-123.md` |
| `jira project --project ABC` | `jira project ABC` |
| `jira filter --project ABC` | `jira filter ABC` |
| `confluence download --id 12345` | `confluence download 12345` |
| `confluence comments --id 12345` | `confluence comments 12345` |
| `confluence create --space ENG --file p.md` | `confluence create p.md ENG` |
| `confluence upload --file 12345.md` | `confluence upload 12345.md` |
| `pr comments --pr 42` | `pr comments 42` |

`--config`, `--out`, `--format` and the other options are unchanged.

## Why `--project` disappears from ticket commands

A ticket key such as `ABC-123` already contains its project. `jira fetch ABC-123` therefore needs no project at all; if you still pass `--project` alongside a ticket id, it is ignored with a warning.

## Where the project or space still has to come from

Commands that have no ticket id to read it from (`jira fetch <project>`, `jira create`, `jira project`, `jira filter`, `confluence create`) resolve it in this order:

1. The argument you pass (`ABC`, or the second argument of `create`).
2. `project` under `[jira]` in the config (`space` under `[confluence]` for `confluence create`).
3. Otherwise the command fails and says how to supply it.

Setting the config default is optional; passing the key explicitly always works. See the [configuration reference](../reference/configuration.md).

## Also new

- Wherever a command takes a ticket, page or PR, you can paste its URL instead: a Jira `/browse/ABC-123` URL, a Confluence `/spaces/ENG/pages/12345/...` URL, a GitHub `/pull/42` URL (which also supplies the repository).
- `jira filter` accepts `--config` and only reads the config when it needs the default project.
